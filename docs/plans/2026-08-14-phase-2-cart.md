# Phase 2 — Cart & Merging Plan

> **Executor:** agent with repo context. Compact; inline code only where non-obvious. Test-first for logic. Explicit return types on all components/hooks/handlers. Remove now-unused imports (lint is a gate).
> **Do NOT push/PR/merge.** Ends with a dev-server verification.

**Goal:** Guest cart (Redux + localStorage) with optimistic add-to-cart, that merges with the saved server cart on login, tears down on logout, and re-hydrates on reload — plus a cart drawer + badge and a demoable add-to-cart surface.

**Ownership (DECISIONS D5/D6):** cart = **Redux**; server persistence via in-app BFF keyed by `uid`; login-merge/logout-teardown via **`createListenerMiddleware`**; guest persistence via a small client persistor (no `redux-persist`).

**Trust model:** the client only asserts `{ productId, quantity }`. The server **re-derives** `title/priceCents/imageUrl/stock` from `seedProducts`, drops unknown ids, and clamps quantity to `[1, stock]`. This keeps merge deterministic and forged prices/quantities out of the (Phase 4) checkout.

**Lifecycle:** `setUser`/`clearUser` also fire on reload-hydration, so add explicit event actions `loggedIn(user)` / `loggedOut()` (same reducer effect) dispatched **only** by the auth forms / logout. Listener middleware keys on those:
- `loggedIn` → `mergeGuestCartOnLogin` (snapshot guest → POST `/api/cart/merge` → `setCart(merged)` → `clearGuestCart`).
- `loggedOut` → `teardownCart` (`clearCart` + `clearGuestCart`). *(No query invalidation — no profile/order queries exist yet; defer to the phase that adds them.)*
- Authed reload: `auth-bootstrap` dispatches `setUser` + `loadServerCart` (GET `/api/cart`).
- Guest: persistor loads/saves localStorage, gated strictly on `status === 'unauthenticated'`.
